# 网络检查

入口：网络管理 → 网络检查（`/network/diagnostics`）。检查从当前 Go 后端进程所在的服务器或容器发起，显示该执行环境的真实主机名、接口地址和可用工具。页面沿用 Motor 外观，按 [DMIT Looking Glass](https://lg.dmit.sh/?server=lax-eb) 组织服务器信息、工具输入和原始输出。

## 工具与使用方式

| 工具 | 执行方式 | 边界 |
| --- | --- | --- |
| ping | 后端向域名、IPv4 或 IPv6 发送 5 个探测包 | 单次等待 2 秒 |
| mtr | 后端输出 10 轮报告，包含路径、延迟和丢包 | 最多 20 跳，间隔 0.5 秒；报告结束前可能没有输出 |
| nexttrace | 后端运行 NextTrace 路径探测 | 最多 20 跳；关闭反向 DNS 和在线地理查询，不展示未经验证的 ASN/地理信息 |
| traceroute | 后端逐跳探测 | 最多 20 跳，每跳 1 次，等待 1 秒 |
| iperf3 客户端（默认） | 后端连接已有 iPerf3 服务端 | TCP，默认 5201 端口、10 秒；允许 1–30 秒，支持反向传输 |
| iperf3 临时服务端 | 后端监听临时端口，页面给出客户端发送/接收命令 | TCP 5201–5204，120 秒后关闭；可提前停止 |

选择“客户端连接后端”后，先等待会话就绪，再从客户端运行页面提供的命令。例如：

```sh
iperf3 -c <可达的后端地址> -p 5201 -t 10
iperf3 -c <可达的后端地址> -p 5201 -t 10 -R
```

执行器使用固定参数的直接进程调用，不接受任意命令或命令行选项。目标支持内网与回环地址，以便运维诊断；拒绝不合法地址、带选项的输入、字面量未指定/组播/链路本地地址和与协议选择冲突的 IP。

## 运行环境

开发和生产 Dockerfile 安装 `ping`、`mtr`、`traceroute`、`iperf3`，并从 Go 模块校验链安装固定版本 NextTrace `v1.7.4` 的官方 Tiny 构建（保留路径探测，排除独立 WebUI/MCP 等服务，安装名为 `nexttrace`）。NextTrace 的构建需要网络下载依赖，首次镜像构建可能较慢。独立部署时，这五个可执行文件必须在后端的 PATH 中。缺少工具时，页面明确标记并禁止启动该工具。

| 环境变量 | 用途 |
| --- | --- |
| `NETWORK_DIAGNOSTICS_NAME` | 显示名称；未设置时使用主机名 |
| `NETWORK_DIAGNOSTICS_PUBLIC_HOST` | 客户端连接命令使用的域名或 IP；不含协议和端口。未设置时使用请求的 Host |

本仓库开发 Compose 将 TCP 5201–5204 映射到宿主机回环地址，并将公开连接地址设为 `localhost`，适合宿主机本地验证。远程部署需要配置客户端可达的真实地址、发布相同的 TCP 端口并放通相应网络路径。网页 API 的 HTTP 反向代理不会自动转发 iPerf3 流量。ICMP 路径工具需要容器允许原始套接字；标准 Docker 的 NET_RAW 能力可满足，受限部署应按运行策略提供该能力。Compose 启用 `init: true` 回收工具产生的孤儿子进程；其他容器部署同样应使用 init 进程。

部署时执行新增迁移 `1792995000000`，它幂等注册页面、四个接口和 `network:diagnostics:run` 按钮权限。沿用现有 JWT、Casbin 和管理员授权。读权限与执行权限分别配置；其他用户或租户不能读取或停止当前用户的任务。

## 生命周期与故障恢复

- 每个用户、租户最多一个普通检查及一个临时服务端；每个后端实例总共最多四个运行进程。
- 普通任务最多运行 60 秒。临时 iPerf3 会话 120 秒后到期。停止、超时和服务退出会终止进程组，回收容量。
- 每个任务最多保留 256 KiB 输出；超过后继续排空进程输出并在页面标明截断。最多保留 128 个任务，完成后最多保留 15 分钟，达到数量上限时提前回收最早完成的任务。
- 浏览器每秒读取快照；轮询失败保留已读内容及任务 ID。“恢复更新”只查询已有任务，不会重新启动检查。切换页面停止轮询，返回后恢复；新建标签页不会继承另一个标签页的会话。
- 任务保存在执行实例的内存中，服务重启后不能恢复。多实例部署需为这组接口保持会话到同一个实例；当前实现不跨实例调度。需要长期留存时下载结果。
- 命令退出成功只代表命令完成，是否存在丢包或路径异常应结合原始输出判断。连接中断时服务器任务仍可能运行，可恢复读取后停止，也会在执行上限到达时结束。

## API

所有响应使用既有 `{code,msg,data}` 信封；请求必须携带 JWT。不得根据 HTTP 200 单独判断业务成功。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/network-diagnostics/server` | 服务器及工具信息 |
| POST | `/api/v1/network-diagnostics/jobs` | 开始任务 |
| GET | `/api/v1/network-diagnostics/jobs/:id` | 读取本人任务快照 |
| DELETE | `/api/v1/network-diagnostics/jobs/:id` | 停止本人任务并返回快照 |

```json
{"tool":"ping","target":"127.0.0.1","family":"auto"}
```

```json
{"tool":"iperf3","mode":"client","target":"127.0.0.1","port":5201,"duration":10,"reverse":false,"family":"4"}
```

```json
{"tool":"iperf3","mode":"server","family":"auto"}
```

`family` 支持 `auto`、`4`、`6`。任务状态为 `running`、`succeeded`、`failed`、`cancelled`、`timed_out`、`expired`。错误码：400 参数无效、404 不存在或不可访问、429 容量占用、503 工具不可用。

验证记录见前端 `docs/NETWORK_DIAGNOSTICS_VALIDATION.md`。本地回环测试只证明工具链和交互链路，不证明公网端口、防火墙、生产多实例或真实线路的吞吐量。
